# אסטרטגיית בדיקות

## בדיקות שקיימות בתשתית

| פקודה                    | מה היא מוכיחה                                    |
| ------------------------ | ------------------------------------------------ |
| npm run format:check     | אחידות עיצוב קבצים                               |
| npm run lint             | כללי קוד סטטיים                                  |
| npm run typecheck        | התאמת טיפוסים ביישומים ובכלי הבדיקה              |
| npm test                 | חוזה זמינות מול מוכנות ומצב תלות לא מוכנה        |
| npm run build            | בניית חבילות ויישומים                            |
| npm run test:integration | בידוד אמיתי במסד, הרשאות תפקיד והקשרים ממוחזרים  |
| npm run test:e2e         | דפדפן עם ממשק, שרת ומסד; שגיאה והתאוששות; מסך צר |

בדיקות המסד כוללות קריאה, הוספה, שינוי, מחיקה והעברה אסורה לעסק אחר;
ניקוי הקשר אחרי הצלחה וכשל; מקביליות; חסימת שינוי מבנה; ופעולה מותרת בתוך
העסק. הן משתמשות בתפקיד הריצה האמיתי, לא בחיקוי או בחשבון מנהל.

בדיקת הדפדפן קוראת למסד דרך שרת אמיתי. בדיקה נפרדת מדמה תשובת 503 כדי
לבדוק את חוויית הכשל; היא אינה הוכחה לבידוד או לזמינות מסד.
בדיקת מקלדת ומסך צר אינה ביקורת נגישות מלאה.

## שער לכל שינוי

1. format:check, lint, typecheck, בדיקות רלוונטיות ובנייה.
2. לשינוי SQL/הרשאות/הקשר עסקי: בדיקות שילוב והפעלה חוזרת של גרסאות.
3. לשינוי תהליך משתמש או חוזה ממשק: בדיקות דפדפן ותרחישי כשל.
4. שינוי הגנה דורש בדיקה של הפעולה המותרת ושל ניסיון עקיפה.
5. תיעוד פקודה, תאריך, תוצאה, כמות בדיקות ומגבלות ביומן הניסוי.

תהליך הבדיקות המרוחק מוגדר ב־.github/workflows/ci.yml. הצלחה מקומית אינה
מוכיחה שהתהליך המרוחק רץ. אין בדיקות עסקיות לתכונות שטרם מומשו.

## לפני מסחור

נדרשים בנוסף תהליכים עסקיים מלאים, טבלת הרשאות, אימות רב־שלבי,
חיבורים וחיוב במצבי כשל, בדיקות עומס, סקירת נגישות, בדיקת חדירה ושחזור
גיבוי נמדד. התנאים מפורטים ב־P16 בתוכנית. שום יעד זמינות או עמידה משפטית
אינו מוכח על ידי בדיקות התשתית הנוכחיות.
