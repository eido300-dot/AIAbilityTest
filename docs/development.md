# סביבת פיתוח

## דרישות

Node.js בגרסה המופיעה ב־.nvmrc, npm מסדרה 11, דוקר פעיל ותוסף compose.
הפקודות מופעלות משורש המאגר. השתמשו ב־checkout הקיים; אין צורך ב־worktree.
ההגדרות המקומיות והנתונים הם לפיתוח בלבד ואינם תצורת ייצור.

## התקנה והפעלה ראשונה

```bash
npm ci
npm run setup:local
npm run db:up
npm run db:migrate
npm run build
npm run dev
```

setup:local מייצר פעם אחת קובץ .env מוחרג עם סיסמאות אקראיות והרשאות קובץ
מצומצמות. הפעלה חוזרת שומרת קובץ קיים. אין להעתיק אליו נתוני ייצור או
להדפיסו. אין צורך במפתח ספק או בסוד ארגוני לשלב התשתית.

ברירות המחדל המקומיות: ממשק ביציאה 5173, שרת ביציאה 3001 ומסד ביציאה 54329. כולם מאזינים בממשק הלולאה המקומית. השרת זמין תחת /api/v1;
שרת הפיתוח של הממשק מעביר אליו בקשות /api.

אין לקבע NODE_ENV בקובץ המשותף: כלי הבנייה וההרצה בוחרים מצב מתאים.
בפריסה עתידית יש להגדיר מצב ייצור בתהליך השרת ובתהליך בניית הממשק.

בדיקות מוכנות מתוך המכונה:

```bash
curl --fail --silent http://127.0.0.1:3001/api/v1/health/live
curl --fail --silent http://127.0.0.1:3001/api/v1/health/ready
```

הראשונה בודקת תהליך; השנייה בודקת מסד ותפקיד חיבור. מסך הסטטוס מציג את
תוצאת השנייה. אין עדיין מסך כניסה או נתיב לקוחות.

## בדיקות

```bash
npm run check
npm run test:integration
npx playwright install chromium
npm run test:e2e
```

אם מותקן כרומיום מערכתי אפשר להשתמש בו בלי הורדה נוספת:

```bash
PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium npm run test:e2e
```

בדיקות הדפדפן מפעילות שרתים בעצמן ודורשות את יציאות 3001 ו־5173 פנויות.
יש לעצור קודם שרתי פיתוח שמופעלים ידנית. בדיקות המסד דורשות db:up וגרסאות
מבנה מעודכנות; אין דילוג שקט אם המסד חסר.

בדיקות השילוב יוצרות נתונים עם מזהים אקראיים ומנקות אותם. הריצו אותן רק
נגד מסד פיתוח ייעודי, לעולם לא נגד מסד ייצור. אין שליחת מידע לספקים.

## מבנה ופיתוח שוטף

- npm run build בונה תחילה את חבילת המסד ואחר כך את היישומים.
- npm run dev בונה את חבילת המסד לפני הפעלת השרת והממשק.
- לאחר שינוי בחבילת המסד יש לבנות אותה מחדש ולהפעיל מחדש את שרת הפיתוח.
- שינוי מבנה נעשה בקובץ SQL חדש תחת packages/database/migrations.
- db:migrate משתמש בחשבון הניהול, בנעילה ובעסקה לכל קובץ, ובודק סכום
  ביקורת כדי למנוע עריכת היסטוריה. הפעלה חוזרת מדלגת על קבצים זהים.
- חשבון crm_app נוצר באתחול כרך דוקר ריק. בייצור הקמת תפקיד והענקת
  הרשאות ייעשו במסלול ניהול מבוקר, לא דרך חשבון היישום.
- עצירת המסד: npm run db:stop. הכרך נשמר. אין להשתמש במחיקת כרכים לפתרון
  תקלה בלי לוודא שלא מאבדים נתונים ולקבל הוראה מפורשת כשנדרש.

## פתרון תקלות

- דוקר אינו נגיש: יש להפעיל מנוע דוקר; אין להסיק שהיישום תקין בלעדיו.
- יציאה תפוסה: בדקו תהליכים לפני עצירה. אל תעצרו שירות שלא הפעלתם.
- שגיאת חיבור לאחר שינוי סיסמה: שינוי .env לא משנה סיסמה בכרך קיים.
  השתמשו בנתיב ניהול לעדכון תפקיד; אל תמחקו כרך כדי להסתיר חוסר התאמה.
- כשל באתחול תפקיד: בדקו הרשאת קריאה/הרצה של סקריפט האתחול ואת יומן
  המסד. אין לחשוף סיסמאות או להדפיס הגדרות compose מורחבות.
- קוד שגיאה בעדכון מבנה: בדקו זמינות תפקיד crm_app ושלמות SQL. אין לשנות
  גרסה שכבר יושמה; הוסיפו תיקון חדש או חקרו כשל שטרם הוחל.
- מטמון npm נשמר ב־.cache/npm בתוך המאגר ומוחרג, כדי לא לדרוש כתיבה לבית
  המשתמש בסביבת ענן. קובץ הנעילה נשמר במאגר.

## מה אינו נשמר כתהליך חי

פרסום תמונת סביבת ענן אינו מבטיח ששרת, דוקר או חיבור נשארים פעילים.
יש לבדוק דוקר, להפעיל db:up, להריץ db:migrate ולהפעיל npm run dev מחדש.
אין להשתמש בשרת הפיתוח להפעלה ציבורית.
